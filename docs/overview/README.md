локального приложения на синтетических данных. Серверные процессы объясняются
схемой: видео не выдаёт статическое демо за развёрнутый сервер.

## Пересборка

Нужны Node.js, зависимости frontend, Chromium для Playwright и FFmpeg/ffprobe.
Проверка воспроизведения использует установленный Google Chrome с поддержкой H.264
в отдельном временном профиле, без пользовательских данных браузера.
Контейнеры, PostgreSQL, S3 и серверная модель для сборки обзора не запускаются.

Из корня репозитория, в первом терминале:

```bash
npm --prefix frontend ci
npm --prefix docs/diagrams ci
npm --prefix frontend exec -- playwright install chromium
npm --prefix frontend run dev:demo -- --host 127.0.0.1 --port 4180 --strictPort
```

Во втором:

```bash
node docs/overview/render.mjs --capture
node docs/overview/check.mjs
```

`OVERVIEW_APP_URL` задаёт другой локальный адрес. `--stills-only` проверяет
вёрстку и обновляет обложку без кодирования MP4; без `--capture` используются
сохранённые кадры. Контрольные кадры сохраняются локально в `output/overview-qa/`.

Результат: H.264, 1600 × 900, 24 кадра/с. Монтаж рассчитывается с шагом
12 кадров/с; FFmpeg дублирует кадры до частоты выходного файла.
Для просмотра с главами достаточно открыть `index.html` рядом с MP4.
